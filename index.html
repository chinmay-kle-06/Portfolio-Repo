PROJECT OVERVIEW

Complaint Management System (CMS) - Digital grievance platform for KLE Tech.

Problem Statement

Manual complaint handling at KLE Tech leads to delays, lost grievances, and minimal transparency. Paper-based or verbal submissions often disappear without a record, leaving students and faculty without confirmation or follow-up. The CMS replaces this process with a secure, auditable portal that preserves anonymity when needed and ensures every grievance is tracked to resolution.

Use Case Scope

The CMS supports the full grievance lifecycle: authenticated complaint submission, evidence upload, status tracking, assignment, escalation, and reporting. It is designed for students, faculty, admins, HODs, and workers, with a secure login layer and contextual dashboards for each role.

  • Complaint categories: Academic, Hostel, Canteen, Network, Electrical, Plumbing.
  • Submission flow: Generate unique IDs (e.g., CMS-2026-014), attach proof, and toggle anonymous filing.
  • Escalation & SLA: Complaints unresolved beyond five working days automatically route to the HOD.
  • Notifications: Real-time dashboard alerts and email confirmations for every complaint stage.

Objectives & Features

  • Centralized Portal: Single platform for all KLE grievance submissions with KLE email authentication.
  • Interactive Dashboard: Live status panels for Total Lodged, Pending Review, In Progress, and Resolved cases.
  • Complaint Tracking: Users can view complaint history, status, assigned workers, and campus site details.
  • Student Privacy: Optional anonymous submission masks identity from field technicians while preserving case continuity.
  • Documented Workflow: Each complaint follows a defined pipeline from submission to resolution and report generation.

Target Users & Roles

Students & Faculty

Submit new grievances, upload evidence, view complaint status, and receive confirmation emails and dashboard alerts.

Admins & HODs

Assign complaints, set priorities, monitor escalation SLAs, and manage institutional workflow compliance.

Workers

Receive assigned tasks, update progress, and close complaints with documented actions.

Submit Complaint Sequence
  • 1 Student/Faculty submits complaint via form with category, description, and optional evidence.
  • 2 Frontend sends POST /api/complaints with Bearer token and complaint payload.
  • 3 Server verifies JWT and user role, then persists a complaint document with a unique ID.
  • 4 System triggers email alerts and dashboard updates for both user and administrator.
User Login & Auth Flow
  • 1 User enters KLE email and password on the login page.
  • 2 API checks the appropriate multi-role user collection in MongoDB.
  • 3 bcrypt.compare() validates the password hash.
  • 4 Valid users receive a JWT token and are redirected to their role-based dashboard.
